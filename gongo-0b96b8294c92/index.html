1. 배경과 목적

우리 회사가 챙겨야 하는 사업 공고와 R&D 과제 공고는 NTIS, IRIS, KAIA, 나라장터 등 여러 사이트에 흩어져 올라옵니다. 지금은 사람이 사이트마다 직접 들어가 확인해야 하고, 그러다 보니 확인이 밀리거나 마감 임박에야 발견하는 일이 생깁니다. 공고는 놓치면 그 자체로 기회 손실입니다.

이 일을 자동화합니다. 아래에 정리한 수집 대상 사이트들을 매일 자동으로 긁어와, 우리 사업과 관련된 공고만 한 화면에서 볼 수 있는 웹페이지를 만들어 주세요. 완성되면 팀 전원이 매일 아침 링크 하나만 열어 그날의 신규 공고를 확인하는 것이 목표입니다.

2. 만들 것

회사 관련 키워드에 걸리는 공고를 모아 보여주는 웹페이지 하나입니다. 화면은 단순해도 됩니다. 핵심은 세 가지입니다.

  1. 매일 자동 수집. 사람이 실행 버튼을 누르지 않아도 매일 아침 최신 상태가 되어 있어야 합니다.
  2. 새 공고가 바로 보일 것. 전일 대비 신규 공고에 NEW 표시, 마감 임박(D-7 이내) 공고에 D-day 표시.
  3. 수집이 죽으면 죽었다고 보일 것. 소스별 최근 수집 시각과 성공/실패 상태를 화면에 표시합니다. 조용히 멈춘 수집기는 없는 것보다 나쁩니다(오래된 정보를 최신으로 믿게 됩니다).

5. 화면 요구사항

  • 목록 칼럼: 출처, 공고명(원문 링크), 공고일, 마감일, 예산(있으면), 상태(NEW / D-n)
  • 정렬 기본값은 공고일 최신순, 마감일순 전환 가능
  • 출처(1군·2군·3군, 기관별)와 키워드로 필터
  • 상단에 수집 현황판: 소스별 최근 수집 시각과 성공/실패
  • 휴대폰에서도 목록이 읽히는 반응형(팀원들이 이동 중에 봅니다)
  • 공고 원문은 저장하지 말고 항상 원 사이트 링크로 연결(저작권·최신성 문제 회피)

6. 기술 가이드

구현 방식은 자율입니다. 다만 아래는 시행착오를 줄이는 힌트이니 참고해 주세요.

  • 스크래핑보다 공식 API를 먼저 확인. 공공데이터포털(data.go.kr)에서 "나라장터 입찰공고정보", "기업마당 지원사업정보", "NTIS" 등을 검색하면 무료 Open API가 나옵니다. API가 있는 소스는 API로 받는 것이 차단 위험 없이 안정적입니다.
  • 스크래핑하는 소스는 예의를 지킬 것. 하루 1~2회, 게시판 목록 페이지만 가져옵니다. 로그인 뒤 영역이나 첨부파일 대량 수집은 하지 않습니다.
  • 서버가 꼭 필요하지 않습니다. 파이썬 수집 스크립트가 매일 정해진 시각에 돌고 결과를 정적 HTML이나 JSON으로 뱉어 GitHub Pages에 올리는 구조면 서버 비용 없이 됩니다. 회사 GitHub(common-Verty) Pages를 이미 쓰고 있으니 그 방식을 권합니다. 구글 시트 + Apps Script로 시작해도 됩니다.
  • 수집 이력을 남길 것. 공고 ID 기준으로 어제 목록과 비교해야 NEW 표시가 됩니다. 수집 실패도 기록해서 현황판에 올립니다.
  • 일부 사이트(KRIT, 나라장터 등)는 자바스크립트로 렌더링되어 단순 요청으로는 빈 페이지가 옵니다. 이런 곳은 API 우선으로 찾고, 없으면 렌더링 도구(Playwright 등)를 쓰거나 모바일·구버전 페이지를 찾아보세요.

8. 완료 기준

  1. 14개 소스가 연결되어 있다(수집 불가 소스는 사유가 현황판에 명시되어 있다)
  2. 매일 아침 9시 이전에 자동으로 갱신된다
  3. 키워드 필터, NEW 표시, 마감 D-day 표시가 동작한다
  4. 소스별 최근 수집 시각과 성공/실패가 화면에 보인다
  5. 팀원 누구나 링크로 접속되고 휴대폰에서도 읽힌다
  6. 운영 문서 1쪽이 있다(소스 추가 방법, 키워드 수정 방법, 수집이 멈췄을 때 확인 지점)
