노션 업무요청 기능, 전체 순환 모델에 맞춰 구현

요청 발신부터 결과 회신, 드라이브 저장, 위키 환류까지 한 바퀴로 도는 업무 구조를 공유하고, 노션 쪽에서 확인하고 구현해 주실 항목을 정리한 업무지시서입니다.

담당: 구창규 선임 요청자: 김동우 요청일: 2026-08-10(월) 1차 회신 8/12(수) 15시 · 왕복 시연 8/14(금) 15시 업무지시서 v1.1

1. 배경과 목적

구창규 선임이 노션으로 업무를 요청하고 관리하는 기능을 만들고 있습니다. 그 기능이 잘 맞물리도록, 회사 업무가 도는 전체 그림을 이 문서로 확정해 공유합니다. 핵심은 노션 기능을 따로 설계하는 것이 아니라, 이미 돌고 있는 요청 포맷과 드라이브, 위키 파이프라인 사이의 가운데 축으로 앉히는 것입니다.

업무는 메시지 카드와 HTML 지시서로 요청되고, 결과는 HTML 보고와 산출물 파일로 노션에서 오가며, 그 파일이 구글드라이브에 저장되어 회사 위키로 자동 환류됩니다. 위키에 쌓인 자료는 다음 요청의 근거가 되므로 일이 돌수록 회사 지식이 쌓이는 구조입니다.

지금 보고 계신 이 문서 자체가 아래 모델 1단계의 실물 예시입니다. 카톡 카드 한 건과 지시서 한 건이 한 세트로 나가고, 같은 구조가 노션 카드에 그대로 얹히면 됩니다.

2. 전체 순환 모델

단계오가는 것비고
1. 요청 발신카톡 카드([업무요청], 할 일·담당·기한 필수) + 상세 건은 HTML 지시서. 지시서 열람은 PDF 링크가 표준포맷 v1.2 확정, 변경 없음
2. 노션 보드 등록카드 필드가 보드 속성에 1:1로 실리고, 지시서 PDF 링크는 '링크' 속성, AI 컨텍스트는 본문 브리프로이번 구현 대상
3. 수행 · 결과 회신담당자가 결과 보고를 HTML(+PDF)로 만들고 산출물 파일과 함께 회신. 카드 상태 갱신, 카톡 원 메시지에 완료 답장이번 구현 대상(동선)
4. 드라이브 저장보고서와 산출물 파일은 드라이브 회사 아카이브 폴더에 저장하고, 노션 카드에는 그 링크만 남긴다1순위 후보는 팀_드롭박스(요청 4)
5. 위키 환류드라이브에 들어온 자료를 매일 아침 파이프라인이 색인·요약·전문검색으로 자동 편입(공유 가능 자료만, 민감 자료 제외)구현 불필요, 이미 가동 중

3. 역할 분담 원칙

축역할원칙
카톡알림과 대화요청, 접수, 완료가 원 메시지의 답장 스레드로 남는다
노션대장과 현황판조율하고 표시한다. 파일 원본을 쌓지 않고 링크를 건다. 제목에 [업무요청] 접두는 붙이지 않는다
드라이브파일 정본지시서, 보고서, 산출물 모두 드라이브에 저장된 것이 원본이다
팀 위키재사용드라이브에 쌓인 자료가 검색 가능한 회사 지식이 되어 다음 업무의 근거로 쓰인다

4. 확인·구현 요청 (5건)

구현 방식은 자율입니다. 아래는 순환이 끊기지 않기 위한 접점 조건이고, 이 조건만 맞으면 내부 구조는 편하신 대로 하시면 됩니다.

요청 1보드 속성 정합 확인.

보드 속성은 회사 표준 필드맵(field_map.json, 2026-07-02 재설계)과 1:1이 원칙입니다. 전체 속성명과 선택값은 6절 표에 그대로 옮겨 두었습니다. 이미 만드신 속성명이 다르면 어느 항목이 다른지만 회신해 주세요. 카톡 포맷과 지시서 구조는 그대로 두고 매핑표 쪽만 맞추면 됩니다.

요청 2카드 등록 동선.

요청 한 건이 들어오면 제목, 담당, 기한, 내용·결과물이 속성으로 실리고, 지시서 PDF 링크가 '링크' 속성에, AI 컨텍스트가 카드 본문 브리프에 들어가는 형태를 확인해 주세요.

요청 3완료 회신 동선.

담당자가 일을 끝내면 카드에 결과 보고(HTML·PDF)와 산출물 파일의 드라이브 링크가 남고, 상태 흐름(배정됨, 진행중, 완료와 수락·완료확인)이 6절 대응표대로 움직이는 형태를 확인해 주세요.

요청 4산출물을 받을 드라이브 폴더 합의.

완료 산출물이 저장될 드라이브 폴더 체계를 함께 정하시죠(회사 아카이브 제자리 원칙). 1순위 후보는 팀 위키의 팀_드롭박스 폴더입니다. 여기는 파일을 넣기만 하면 다음날 아침 자동 분류·색인이 이미 돌고 있어서, 이대로 쓰면 노션 쪽에 추가로 만들 것이 없습니다. 이 폴더로 통일할지, 사업별 아카이브 폴더 직접 저장을 병행할지만 정하면 됩니다.

요청 5카톡 반자동 적재 방향 회신.

카톡의 [업무요청] 메시지를 보드에 반자동으로 싣는 단계(기존 카톡 수집 파이프라인과 노션 적재기 재사용 후보)를 진행할지, 어떤 방식이 좋을지 의견을 주세요. 선임 구현 방향을 확인한 뒤 결정하기로 보류해 둔 항목입니다.

7. 진행 단계와 기한, 완료 기준

1차(방향 회신): 8/12(수) 15시까지. 요청 1·4·5에 대한 답이면 됩니다. 형식은 자유롭게, 노션 페이지나 카톡 답장이면 충분합니다.

완성(왕복 시연): 8/14(금) 15시까지. 업무요청 카드 한 건을 등록부터 완료 회신까지 실제로 돌려서 보드 링크를 공유해 주세요. 이 지시서 건을 그대로 테스트 카드로 쓰셔도 됩니다.

일정이 빠듯하면 접수 답장 때 협의해 주세요. 완료 보고는 카톡의 원 업무요청 메시지에 답장으로 부탁드립니다.

완료 기준 체크리스트

  • 보드 속성이 field_map.json과 1:1이거나, 다른 항목이 회신으로 정리됐다
  • 테스트 카드 1건이 등록부터 완료 회신까지 실제로 돌았고, 카드에 지시서 링크와 결과물 링크가 남았다
  • 상태와 수락, 완료확인이 6절 대응표대로 움직였다
  • 완료 산출물을 받을 드라이브 폴더가 합의됐다
  • 반자동 적재(요청 5)에 대한 의견이 회신됐다
